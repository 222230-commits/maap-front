توثيق واجهات لوحة تحكم الأدمن

دليل تقني كامل موجّه لمطوّر Angular، يغطي كل نقاط النهاية (Endpoints) الخاصة بلوحة تحكم الأدمن — الطلبات، الاستجابات، قواعد التحقق، وأفضل طريقة لعرض كل جزء في الواجهة مع مثال بصري توضيحي.

المصادقة (Authentication)

كل الروابط محمية بـ auth:sanctum + IsAdmin. أرسل الهيدر التالي مع كل طلب بعد تسجيل الدخول عبر POST /admin/login:

Authorization: Bearer {token}
Accept: application/json
Content-Type: application/json
أنشئ AuthInterceptor واحد يحقن التوكن تلقائياً في كل طلب، ويتعامل مع رد 401 بتسجيل خروج فوري وإعادة توجيه لصفحة الدخول.

تسجيل الخروج

POST/admin/logout
يُبطل توكن الجلسة الحالي على السيرفر (Sanctum). استدعِه ثم امسح التوكن محلياً (localStorage/Signal) ووجّه المستخدم لصفحة الدخول — لا تعتمد على مسح التوكن محلياً فقط دون استدعاء هذا الـ Endpoint.

شكل الاستجابة الموحّد

ابنِ Interface عام واحد بدل تكراره في كل خدمة:

// core/models/api-response.model.ts
export interface ApiResponse<T> {
  success: boolean;
  message?: string;
  data: T;
  error?: string;
  errors?: Record<string, string[]>; // أخطاء التحقق 422
}
شكل الـ Pagination يختلف بين الأقسام: بعضها يُرجع كائن Laravel Paginator القياسي داخل data، وبعضها (المتاجر، المنتجات) يُعيد تغليفه يدوياً بحقول pagination منفصلة. تحقّق من الشكل الموثّق تحت كل Endpoint تحديداً ولا تفترض نمطاً موحداً.

03 · Seller Actions

إدارة التجار (حظر / حذف مرتبط بالمتجر)

عمليتان حساستان فقط، منفصلتان لأنهما تؤثران على التاجر ومتجره معاً ضمن Transaction واحدة.

POST/admin/sellers/{id}/toggle-status
يعكس حالة التاجر و متجره معاً في نفس اللحظة.
{
  "success": true,
  "message": "تم حظر التاجر بالكامل وتجميد متجره...",

يحذف المتجر ناعماً، يسحب التوكنز (تسجيل خروج فوري)، ويطمس بيانات التاجر الشخصية.

05 · Shops

إدارة المتاجر

قائمة، تفاصيل، تحليلات مبيعات دقيقة (طلبات مكتملة فقط)، وحذف جذري شامل.

GET/admin/shops
Query: status, search (يبحث أيضاً في بيانات التاجر المالك), per_page
GET/admin/shops/{id}
تفاصيل المتجر مع seller, categories, badges، وعدّادات products_count / followers_count / orders_count.
POST/admin/shops/{id}/toggle-status
عكس بسيط لحالة is_active للمتجر فقط (بدون التأثير على حساب التاجر نفسه — للتمييز عن مسار 03 الذي يحظر الاثنين معاً).
GET/admin/shops/{id}/analytics
{ "analytics": { "total_sales": 154320.50, "total_orders": 212, "latest_orders": [...] } }
الأرقام تُحسب من الطلبات المؤكدة من الطرفين فقط. اعرضها كـ "صافي المبيعات المؤكدة" لتفادي التباس الأدمن مع إجمالي كل الطلبات.
GET/admin/shops/{id}/orders
سجل طلبات المتجر مع Pagination عبر per_page (افتراضي 15). الاستجابة تتضمن أيضاً shop_name.
DELETE/admin/shops/{id}/deleteالأخطر في النظام
يخفّض رتبة التاجر إلى زبون، يحذف كل منتجاته وينظفها من كل السلات وقوائم الأمنيات لدى كل المستخدمين. يحتفظ بسجلات الطلبات التاريخية فقط.

06 · Categories

التصنيفات — بنية شجرية (حتى 5 مستويات)

أكثر الوحدات تعقيداً من ناحية الواجهة؛ يجب استخدام مكوّن شجري حقيقي وليس جدولاً مسطحاً.

GET/admin/categories
typeشكل data
treeArray شجري متداخل (children)
main / subArray مسطّح
all / trashedLaravel Paginator
GET/admin/categories/dynamic
Query: parent_id (اختياري، UUID). تحميل كسول (Lazy Loading) للأبناء عند الطلب — استخدمها فقط إن اخترت بناء الشجرة بنمط Lazy Node بدل جلب type=tree كاملة دفعة واحدة.
POST/admin/categories/store
الحقلالقاعدة
nameمطلوب، نص، حد أقصى 255
parent_idاختياري، UUID موجود فعلياً
image_urlاختياري، نص (رابط)
GET/admin/categories/{id}/show
تفاصيل تصنيف واحد + الأبناء المباشرين + اسم الأب parent_name.
PUT/admin/categories/{id}/update
نفس حقول الإنشاء (كلها اختيارية). يحمي تلقائياً من جعل التصنيف أباً لنفسه أو نقله ليصبح تابعاً لأحد أبنائه — عطّل بصرياً هذه الخيارات في الفورم لتجربة أفضل، لكن لا تعتمد على الفرونت فقط كحماية وحيدة.
POST/admin/categories/{id}/restore
استعادة تصنيف من سلة المحذوفات (يعمل فقط على العناصر المحذوفة ناعماً — onlyTrashed).
POST/admin/categories/{id}/move-branch
الباك إند يحمي من: النقل داخل النفس، الحلقات المغلقة (نقل فرع ليصبح تابعاً لأحد أحفاده)، وتجاوز سقف 5 مستويات عمق. عند الرفض (400) أعد العنصر بصرياً لمكانه الأصلي.
DELETE/admin/categories/{id}/destroy
يُرفض (400) إن كان للتصنيف منتجات مرتبطة (حتى بأعماقه) أو أبناء مباشرون.

07 · Products

إدارة المنتجات

فلترة شجرية للأقسام (تشمل الفروع تلقائياً)، ونقل جماعي بالتحديد المتعدد.

GET/admin/products
Queryملاحظة
taball / active / blocked
statuspublished / unpublished
category_idيشمل تلقائياً كل التصنيفات الفرعية تحته (CTE)
شكل الـ Pagination هنا مختلف — حقول total, count, per_page, current_page, total_pages منفصلة عن data (وليست كائن Paginator قياسي).
POST/admin/products/{id}/toggle-approval
يعكس is_active للمنتج (حظر/إظهار). Response يتضمن is_active الجديدة مباشرة — استخدمها للتحديث الفوري (Optimistic UI) بدل إعادة جلب القائمة كاملة.
GET/admin/products/trending
أعلى 10 منتجات حسب عدد مرات الإضافة للمفضلة. لا Pagination — Array ثابت الحجم.
{ "data": [{ "id": "uuid", "title": "...", "price": 250, "favorites_count": 340 }] }
POST/admin/products/move-products
استخدم product_ids أو from_category_id (وليس الاثنين). يُرفض (422) إن كان الهدف تصنيفاً رئيسياً أو له أبناء.
يوجد destroy() لحذف منتج مفرد داخل الكونترولر لكن بلا Route مسجَّل في admin.php. لا تُضِف زر حذف منفرد قبل تأكيد إضافة الراوت من الباك إند.
