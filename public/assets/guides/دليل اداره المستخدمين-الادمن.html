لوحة الأدمن — إدارة المستخدمين (الزبائن والتجار)

دليل تقني شامل لربط واجهة Angular بمسارات إدارة المستخدمين في الباك إند (Laravel). يغطي كل Route فعلي، شكل الطلب والاستجابة مع الإحصائيات المتفرعة الجديدة للمشترين والتجار، الفخاخ الخفية في الكود، ومخططات توضيحية[cite: 10].

1. نظرة عامة واختيار الأداة

الميزةالأداة المقترحةالسبب
قائمة المستخدمين + إحصائيات + فلترة Angular — جدول بتبويبات ديناميكية الباك إند أصبح يوفر أعداداً متفرعة (للكل، النشطين، المحظورين) لكل من الزبائن والتجار في استجابة واحدة[cite: 10].
عرض تفاصيل زبون + سجل طلبياته Angular — شاشة تفصيلية بتبويبين تحتاج جلب مسارين منفصلين (show + orders) وعرضهما معاً دون تشارك كاش[cite: 9].
تعديل بيانات المستخدم Angular — Reactive Form داخل مودال الباك إند الآن يدعم تعديل بيانات الزبون والتاجر في نفس المسار[cite: 10].
حظر/تفعيل وحذف الحساب Angular — أزرار إجراء + مودال تأكيد للحذف عملية الحذف حساسة وغير قابلة للتراجع من واجهة الأدمن، فتحتاج تأكيداً صريحاً[cite: 9].

2. GET /admin/users — قائمة المستخدمين مع الإحصائيات المتفرعة

GET/admin/users?role=all&status=all&search=

تم تحديث هذا المسار ليدعم جلب كافة الأنواع ويوفر إحصائيات متفرعة جاهزة للتبويبات[cite: 10]:

الحقلالقيم المسموحةملاحظة
roleall / buyer / sellerاختياري، الافتراضي all[cite: 10]
statusall / active / bannedاختياري، الافتراضي all[cite: 10]
searchنص حتى 100 حرفيبحث في الاسم، البريد، الهاتف، واسم المتجر للتاجر[cite: 10]

استجابة النجاح — 200 (النسخة المحدثة)

{
  "success": true,
  "filters_applied": {
    "role": "all",
    "status": "active",
    "search": null
  },
  "counts": {
    "buyers": {
      "all": 150,
      "active": 140,
      "banned": 10
    },
    "sellers": {
      "all": 45,
      "active": 40,
      "banned": 5
    },
    "total_users": {
      "all": 195,
      "active": 180,
      "banned": 15
    }
  },
  "data": {
    "current_page": 1,
    "data": [ { "id": 12, "role": "buyer", "full_name": "...", "is_active": true } ],
    "total": 180,
    "last_page": 12,
    "per_page": 15
  }
}
توصية تصميم: استخدام كائن counts الجديد استفد من كائن counts لطباعة الأرقام بداخل التبويبات في الفرونت إند مباشرة. الباك إند يقوم بحساب هذه الأرقام في استعلام واحد مجمع لتحسين الأداء حتى أثناء البحث الفعلي[cite: 10].
فخ: حقل data مضاعف المعنى الاستجابة تحوي مفتاح data على مستويين مختلفين: المستوى الأول هو كائن الـ Paginator، والمستوى الثاني بداخله هو المصفوفة الفعلية. أي كود يحاول قراءة المصفوفة مباشرة سيفشل — الصحيح هو response.data.data[cite: 9].

3. GET /admin/users/{id} — تفاصيل مستخدم محدد

GET/admin/users/{id}
// 200
{ "success": true, "data": { "id": 12, "role": "buyer", "full_name": "...", "email": "..." } }

// 404
{ "success": false, "message": "المستخدم المطلوب غير موجود، أو غير مصرح بعرض بياناته." }
ملاحظة أمنية: هذا المسار يعرض المشترين والتجار المسار يستثني فقط حسابات الأدمن (role != 'admin') ويسمح بجلب الزبائن والتجار بشكل متساوٍ[cite: 10].

4. GET /admin/buyers/{id}/orders — طلبيات الزبون

GET/admin/buyers/{id}/orders
{
  "success": true,
  "orders": {
    "current_page": 1,
    "data": [ { "id": 5, "shop": { "id": 3, "name": "متجر النور" } } ],
    "total": 4
  }
}
فخ: لا يوجد 404 لمعرف غير موجود لا يتحقق الكود من وجود الزبون قبل جلب الطلبات[cite: 9, 10]. صمّم شاشة الطلبيات على أساس "حالة فارغة" وليس "حالة خطأ" عند عدم وجود بيانات[cite: 9].

5. POST /admin/buyers/{id}/toggle-status

POST/admin/buyers/{id}/toggle-status

الحالة تُعكس تلقائياً (true↔false) بناءً على القيمة الحالية في قاعدة البيانات[cite: 9, 10].

// 200
{
  "success": true,
  "message": "تم تجميد حساب الزبون وحظره من الدخول إلى التطبيق.",
  "data": { "id": 12, "is_active": false }
}
فخ: تحديث الحالة من الباك إند فقط يجب على الفرونت الاعتماد على data.is_active القادم من الاستجابة لتحديث الواجهة، وعدم قلب حالة محلية بشكل متفائل لتجنب مشاكل التزامن[cite: 9].

6. PUT /admin/users/{id} — تعديل بيانات الزبون أو التاجر

PUT/admin/users/{id}

تم تحديث هذا المسار ليتمكن الأدمن من تعديل بيانات المشتري أو التاجر[cite: 10].

// Request body (كل الحقول اختيارية)
{
  "full_name": "أحمد علي",
  "phone_number": "0911234567",
  "address": null
}
الحقلالقاعدة
full_nameنص، حتى 255 حرف[cite: 10]
phone_numberيبدأ بـ 091/092/093/094/095 + 7 أرقام[cite: 10]
addressنص أو null[cite: 10]
فخ: null يمسح الحقل عدم إرسال المفتاح إطلاقاً يترك القيمة الحالية دون تغيير[cite: 9]. أي بناء الـ payload يجب أن يكون ديناميكياً[cite: 9].
رسالة نجاح ديناميكية يُرجع المسار رسالة "تم تحديث بيانات الزبون بنجاح" أو "تم تحديث بيانات التاجر بنجاح" بناءً على دور المستخدم role المكتشف[cite: 10].

7. DELETE /admin/buyers/{id} — حذف حساب الزبون

DELETE/admin/buyers/{id}

عملية متعددة الخطوات ضمن Transaction واحدة — إما تنجح كل الخطوات معاً أو تتراجع كلها[cite: 9, 10].

ضغط الأدمن على حذف
بدء Transaction
طمس البيانات الشخصية (Anonymization)حذف التوكنات وتعديل البريد وتصفير الهاتف[cite: 10]
الاحتفاظ بالطلبيات القديمة (Orders)لحماية الأرباح وتقارير النظام[cite: 10]
// 200
{ "success": true, "message": "تم حذف حساب الزبون بنجاح..." }
فخ: الطلبات القديمة لا تُحذف جداول orders وorder_items تبقى كما هي تماماً للحفاظ على تقارير المتاجر المالية[cite: 9, 10].

8. الشاشات الرئيسية في Angular

راجع الدليل السابق للحصول على الـ Mockups للجدول والمودال. الفكرة الأساسية الآن هي الاعتماد على تبويبات علوية للأدوار باستخدام إحصائيات counts المرجعة[cite: 10].

10. نصائح عملية لتفادي الاحتكاك مع الباك إند

  1. استخدم كائن counts في مسار الـ index لطباعة أعداد المشترين والتجار بجميع حالاتهم بشكل متزامن مع البحث والفلترة[cite: 10].
  2. عند قراءة استجابة الـ Pagination اقرأ دائماً من المستوى الداخلي (data.data)[cite: 9].
  3. ابنِ الـ payload الخاص بالتعديل ديناميكياً لتفادي مسح الحقول دون قصد[cite: 9].
  4. عامل شاشة طلبيات الزبون كحالة قابلة للفراغ (Empty State)[cite: 9].
